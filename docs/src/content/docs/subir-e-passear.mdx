Em poucos minutos, a TV aparece no navegador. Este guia mostra como subir o testbed e o que
experimentar em cada tela, conferindo por dentro o que a plataforma fez. O que cada tela é, e por
que existe, está em [A TV 3.0 AoP em 5 minutos](../aop-em-5-minutos/#o-caminho-do-espectador).

## Antes de começar

Você precisa de **Docker** com **Docker Compose v2** e de **Git**.

<Aside type="caution">
No macOS com Apple Silicon, construa as imagens antes de subir (`docker compose build`). No Windows,
o testbed roda dentro do WSL2, com uma configuração própria. Os dois casos estão em
[Instalação](../instalacao/#macos).
</Aside>

## Subir

```bash
git clone --recurse-submodules https://github.com/multisens/TV30.git
cd TV30
cp .env.example .env
./tv30 up
```

O `.env` é obrigatório: sem ele, a TV não sobe e ficam de pé só o banco e a borda. Na primeira vez,
o Docker baixa as imagens, o que leva alguns minutos.

Para conferir, rode `./tv30 status`. Os containers `aop-shell`, `tv3ws`, `aop-cc`, `bcast-sim`,
`edgegateway`, `mqtt-broker` e `redis` devem estar de pé, e o anunciante SSDP, rodando.

A emissora simulada traz três serviços de exemplo, todos no canal 10. O vídeo de cada um é um padrão
de barras com o número do serviço e um contador de quadros, com um bipe a cada segundo, repetido em
loop como se fosse ao vivo.

## Experimente

As telas estão em inglês. Navegue com as setas e confirme com Enter.

<Steps>

1. **Abra a TV.** Acesse `http://localhost:8080`. Abrir a página entrega o controle à plataforma,
   que mostra a escolha de perfil. Já existe um perfil, *Viewer 1*.

   Os perfis ficam no Redis, a memória do receptor. Para ver a lista:

   ```bash
   docker compose exec redis redis-cli SMEMBERS users:index
   ```

   [O que é essa tela](../aop-em-5-minutos/#o-caminho-do-espectador)

2. **Crie um perfil.** Escolha o cartão de novo perfil, dê um apelido e escolha um avatar. Rode o
   comando de novo: aparece um id a mais. Para ver os dados de um perfil, use
   `docker compose exec redis redis-cli HGETALL user:<id>`.

   A plataforma aceita até cinco perfis. O sexto é recusado com a mensagem *O limite de 5 perfis foi
   atingido*.

3. **Entre num serviço.** Escolha um perfil. Aparece o catálogo, com um cartão para cada serviço que
   a emissora simulada anuncia: *Sintetico* (10.1), *Radiodifusao* (10.2) e *Guardada* (10.3).
   Escolha *Radiodifusao*.

   A plataforma sintoniza o serviço e passa a ter um serviço corrente:

   ```bash
   docker compose exec redis redis-cli GET session:current-service-id
   ```

4. **Espere a aplicação da emissora.** A Bootstrap Application mostra o serviço e o vídeo numa
   janela. A aplicação desse serviço vem pelo ar, num carrossel, e só abre depois de passar nele: em
   até 10 segundos, o vídeo vai para a tela cheia e a aplicação aparece por cima dele, dizendo que
   foi entregue pelo carrossel.

   Para ver a aplicação em execução e a origem própria em que ela roda:

   ```bash
   docker compose exec redis redis-cli HGETALL session:current-app
   ```

   No *Sintetico*, a aplicação vem pela internet e abre na hora. No *Guardada*, a plataforma primeiro
   guarda a aplicação inteira no receptor e só então a abre.

   [Como a emissora entrega a aplicação](../emissora-simulada/#os-serviços-de-exemplo)

5. **Volte.** Aperte Esc. A aplicação da emissora termina e a Bootstrap Application volta. O botão
   de voltar leva ao catálogo, e o cartão do perfil, no catálogo, volta à escolha de perfil.

6. **Encontre a TV na rede.** Aparelhos da rede local acham a TV por SSDP e pedem a ela o manifesto,
   que diz onde estão as APIs:

   ```bash
   curl -i http://localhost:44642/manifest
   ```

   A resposta traz, nos cabeçalhos, os endereços das APIs (`Server-BaseURL` e
   `Server-SecureBaseURL`), os métodos de pareamento e o nome da TV.

   [Quem conversa com a plataforma](../aop-em-5-minutos/#quem-conversa-com-a-plataforma)

</Steps>

## Mais para olhar

| O quê | Como chegar |
|---|---|
| As APIs, com a documentação de cada rota | `docker port edgegateway 8085` dá a porta do Swagger |
| O banco, numa interface web | `docker port redis 18081` dá a porta do Redis Commander; usuário `admin`, senha `tv30-redis-admin` |
| O que cada peça registra | `docker compose logs -f aop-shell` (ou `aop-cc`, `bcast-sim`, `tv3ws`) |
| O que a emissora simulada serve | `curl http://localhost:8082/signaling/lls`; o resto está em [Emissora simulada](../emissora-simulada/) |

## Desligar

```bash
./tv30 down
```

Os perfis criados continuam guardados para a próxima subida. Para voltar ao início, só com o
*Viewer 1*, use `./tv30 down -v`, que apaga também os dados guardados.
